# Design Patterns

Read this reference before generating differential expression or GSEA code. Based on inspection, classify and generate code for one of these patterns.

## Shared Template Setup

This section defines the shared variables the pattern code below relies on: `se`, `plotAssay`, `gene.sets`, and `gsea_methods`. SKILL.md Section 2 (Normalization) creates them once, so they are already generated by the time this reference is read. Do not re-define them. Their values:

- `se` — the `basicBulk::tidySE()` output: one SE holding the raw `counts` assay plus the added `logCPM` and (with `adjustBatch = TRUE`) `ComBat` assays, with `Group` and `Sample` in its colData, so `se$Group`, `dplyr::filter()`, and any subset/split columns work directly on it
- `plotAssay` — `"logCPM"` or `"ComBat"` (batch-adjusted)
- `gene.sets` — `basicBulk::getReactome(organism)`

The **GSEA test selection** is also defined once, so the loop, its tidy step, and the GSEA cache key are a single source and can never drift apart:

```r
gsea_methods <- "camera"   # canonical default (see SKILL.md §10 Pathways / references/package-reference.md).
                           # tidyGSEAlist(GSEAmethod = ...) needs a SCALAR; if you ever run several
                           # methods, e.g. c("fry", "camera"), keep this vector for the loop's
                           # methods = but pass a SEPARATE scalar gsea_tidy_method to the tidy call.
```

Every GSEA loop below passes `methods = gsea_methods` and tidies with `tidyGSEAlist(GSEAmethod = gsea_methods)`, and the GSEA cache key hashes the same `gsea_methods` object (`references/output-saving.md` → After GSEA) — so a `camera` ↔ `fry` switch changes the computation and the cache together.

Pass `assay = plotAssay` in downstream visualization calls (the basicBulk plotters default to `assay = "logCPM"`, which leaves out the ComBat adjustment when `adjustBatch = TRUE`); hardcode `"logCPM"` only in the `plotAssay` assignment or intentional default-vs-batch PCA comparison code. Statistics always read `assay = "counts"` in every augere call (augere's default `assay = 1` takes whichever assay comes first), never the logCPM/ComBat assays.

When the user specifies custom cutoffs, define the values once:

```r
logFC_cutoff <- 0.58
FDR_cutoff <- 0.10
```

Replace these example values with the actual user-specified numbers. If the user does not specify custom cutoffs, do not define `logFC_cutoff` or `FDR_cutoff`, and omit cutoff arguments from `basicBulk::makeSigTibble()`, `basicBulk::basicVolcano()`, `basicBulk::basicMA()`, `basicBulk::basicUpset()`, `basicBulk::genePlot()`, and `gg4way::gg4way()`.

The setup chunk creates the output directory tree by default (see SKILL.md Section 1); creating it saves nothing — see `references/output-saving.md` for save patterns. This does not change `augere.de::runVoom()`/`augere.gsea::runContrast()` arguments — always use `output.dir = tempfile()` and `save.results = FALSE` for both.

The `sigTibble` examples below omit custom cutoffs. If `logFC_cutoff` and `FDR_cutoff` were defined, generate:

```r
# compute chunk (build + save; no printing)
sigTibble <- DGEdata %>%
  basicBulk::makeSigTibble(logFCcutoff = logFC_cutoff,
                           FDRcutoff = FDR_cutoff)

# display chunk, under the `## Significant Genes` header (SKILL.md Section 4)
sigTibble %>%
  basicBulk::printSigTibble()
```

## Batch Handling (All Patterns)

Batch adjustment can combine with any pattern — a simple Pattern 1 study can have a Batch column. See SKILL.md "Batch Handling": **both** options use `basicBulk::tidySE(adjustBatch = TRUE)` (no `block = "Batch"`) and `plotAssay = "ComBat"` with the dual PCA — that part is shared. The options differ only in the **statistics** parameter — **Option A** `dc.block = "Batch"` or **Option B** `block = "Batch"` in `augere.de::runVoom`/`augere.gsea::runContrast`. Either way the statistics step reads `assay = "counts"` (raw counts), never the ComBat assay. The pattern-specific notes below cover how that statistics step carries the chosen batch term:
- **Pattern 1/2:** Add `dc.block = "Batch"` (Option A) **or** `block = "Batch"` (Option B) to `runVoom()` and `runContrast()`. Everything else is unchanged.
- **Custom design:** a custom `design =`/`contrasts =` workflow **bypasses** the `groups`/`block`/`covariates` parser, so `block = "Batch"` is silently ignored. For Option B under a custom design, carry batch as a design term instead — `stats::model.matrix(~ 0 + Group + Batch, ...)` (see Custom Design Matrix below). Option A's `dc.block = "Batch"` still works, because it is passed through to `lmFit`.
- **Pattern 3/4:** If Batch is confounded with the subset/split variable (e.g., subsetting by Study where each study is a single batch), omit `block`/`dc.block` for Batch in that subset — the subset already accounts for it. Ask the user when this is ambiguous.

## Pattern 1: Single Model, Simple Comparisons

Default pattern. When: single control group, straightforward pairwise comparisons, standard blocking.

Generate comparison list programmatically with the control as the first level:

```r
comparisonList <- levels(se$Group)[c(2:nlevels(se$Group))] %>%
  purrr::map(~ list(.x, levels(se$Group)[1]) %>%
               purrr::list_c())
```

Run `augere.de::runVoom()`:

```r
voomList <- se %>%
  augere.de::runVoom(groups = "Group",
                     comparisons = comparisonList,
                     block = BLOCK,
                     covariates = COVARIATES,
                     assay = "counts",
                     output.dir = tempfile(),
                     save.results = FALSE) %>%
  magrittr::extract2("results")
```

Only include `block` and `covariates` in `runVoom()`/`runContrast()` when they apply. If there is no blocking or covariates, omit them.

Run `augere.gsea::runContrast()` in a loop because it takes a single comparison; it has no seed argument, so call `set.seed(100)` once before the loop. Every GSEA loop below passes `methods = gsea_methods` (`"camera"`, defined once in Shared Template Setup) — the package default `c("fry", "camera")` also runs the additional deterministic `fry` test (limma's analytic approximation to the `mroast` rotation gene-set test, not a random-rotation test), but `tidyGSEAlist(GSEAmethod = gsea_methods)` extracts only the named `"camera"` result, so `fry` would be discarded compute (opt into it only when you need its self-contained test, then set `gsea_methods` accordingly and tidy with a scalar `GSEAmethod`). For dozens of contrasts, parallelize this loop with furrr — see SKILL.md §10 Pathways.

```r
set.seed(100)
GSEAlist <- comparisonList %>%
  purrr::set_names(purrr::map_chr(., magrittr::extract, 1)) %>%
  purrr::imap(~ augere.gsea::runContrast(se,
                                         sets = gene.sets,
                                         groups = "Group",
                                         block = BLOCK,
                                         covariates = COVARIATES,
                                         comparison = .x,
                                         methods = gsea_methods,
                                         assay = "counts",
                                         output.dir = tempfile(),
                                         save.results = FALSE),
              .progress = TRUE) %>%
  basicBulk::tidyGSEAlist(GSEAmethod = gsea_methods)
```

Then create the DGE data and significance tibble:

```r
# compute chunk (build + save; no printing)
DGEdata <- se %>%
  basicBulk::makeDGEdata(voomList)

sigTibble <- DGEdata %>%
  basicBulk::makeSigTibble()

# display chunk, under the `## Significant Genes` header (SKILL.md Section 4)
sigTibble %>%
  basicBulk::printSigTibble()
```

## Pattern 2: Nested Split via `designTibble`

When: groups encode both a biological context and treatment in their names (e.g., `DrugA (3D)`, `Control (2D)`, `NeuronDrug`, `AstroPBS`). Each comparison is an explicit pair in the `designTibble`, and each `runVoom` call fits a separate model using only those two groups. User must confirm the pattern and pairings.

```r
designTibble <- tibble::tibble(
  exp = EXPERIMENTAL_GROUP,
  control = CONTROL_GROUP,
  name = glue::glue("{exp} vs {control}")
)

voomList <- designTibble %>%
  purrr::pmap(~ with(list(...),
                     augere.de::runVoom(se,
                                        groups = "Group",
                                        comparisons = c(exp, control),
                                        block = BLOCK,
                                        covariates = COVARIATES,
                                        dc.block = DC_BLOCK,
                                        assay = "counts",
                                        output.dir = tempfile(),
                                        save.results = FALSE) %>%
                       magrittr::extract2("results")),
              .progress = TRUE) %>%
  purrr::set_names(designTibble$name) %>%
  purrr::list_c()
```

Only include `block`, `covariates`, and `dc.block` in `runVoom()`/`runContrast()` when they apply. If there is no blocking, covariates, or repeated measures, omit them.

GSEA follows the same `purrr::pmap(~ with(list(...), ...))` pattern. Pass a single comparison to `runContrast()`:

```r
set.seed(100)
GSEAlist <- designTibble %>%
  purrr::pmap(~ with(list(...),
                     augere.gsea::runContrast(se,
                                              sets = gene.sets,
                                              groups = "Group",
                                              comparison = c(exp, control),
                                              block = BLOCK,
                                              covariates = COVARIATES,
                                              dc.block = DC_BLOCK,
                                              methods = gsea_methods,
                                              assay = "counts",
                                              output.dir = tempfile(),
                                              save.results = FALSE)),
              .progress = TRUE) %>%
  purrr::set_names(designTibble$name) %>%
  basicBulk::tidyGSEAlist(GSEAmethod = gsea_methods)
```

Then create the DGE data and significance tibble:

```r
# compute chunk (build + save; no printing)

  basicBulk::makeDGEdata(voomList)

  basicBulk::makeSigTibble()
```

## Pattern 3: Single-Variable Subset via `subset.factor`

When: the same comparisons apply across levels of one variable (e.g., Drug vs PBS run separately for each cell type or tissue). Uses `subset.factor`/`subset.levels` in `runVoom()` to subset samples before fitting, so the Group column stays clean (just treatment names). User must confirm the subset variable.

```r
control <- levels(se$Group)[1]

comparisonList <- levels(se$Group)[c(2:nlevels(se$Group))] %>%
  purrr::map(~ list(.x, control) %>%
               purrr::list_c())

voomList <- unique(se$SUBSET_COL) %>%
  forcats::as_factor() %>%
  purrr::set_names() %>%
  purrr::map(function(subset_level) {
    subset_groups <- se %>%
      dplyr::filter(SUBSET_COL == subset_level) %>%
      dplyr::pull(Group) %>%
      forcats::fct_drop() %>%
      levels()

    if (!control %in% subset_groups || length(subset_groups) < 2) {
      message(glue::glue("Skipping {subset_level} — control missing or fewer than 2 groups"))
      return(NULL)
    }

    valid_comparisons <- comparisonList %>%
      purrr::keep(~ all(.x %in% subset_groups))

    if (length(valid_comparisons) == 0) {
      message(glue::glue("Skipping {subset_level} — no valid comparisons"))
      return(NULL)
    }

    results <- augere.de::runVoom(se,
                                  groups = "Group",
                                  comparisons = valid_comparisons,
                                  subset.factor = "SUBSET_COL",
                                  subset.levels = subset_level,
                                  assay = "counts",
                                  output.dir = tempfile(),
                                  save.results = FALSE) %>%
      magrittr::extract2("results")
    purrr::set_names(results, glue::glue("{subset_level}:{names(results)}"))
  }, .progress = TRUE) %>%
  purrr::compact() %>%
  purrr::list_c()
```

Replace `SUBSET_COL` with the actual colData column to subset by (e.g., `"CellType"`, `"Tissue"`). Only include `block`, `covariates`, and `dc.block` when they apply.

GSEA follows the same pattern with the same per-subset guard:

```r
set.seed(100)
GSEAlist <- unique(se$SUBSET_COL) %>%
  forcats::as_factor() %>%
  purrr::set_names() %>%
  purrr::map(function(subset_level) {
    subset_groups <- se %>%
      dplyr::filter(SUBSET_COL == subset_level) %>%
      dplyr::pull(Group) %>%
      forcats::fct_drop() %>%
      levels()

    if (!control %in% subset_groups || length(subset_groups) < 2) {
      return(NULL)
    }

    valid_comparisons <- comparisonList %>%
      purrr::keep(~ all(.x %in% subset_groups))

    if (length(valid_comparisons) == 0) {
      return(NULL)
    }

    valid_comparisons %>%
      purrr::set_names(purrr::map_chr(., magrittr::extract, 1)) %>%
      purrr::imap(~ augere.gsea::runContrast(se,
                                             sets = gene.sets,
                                             groups = "Group",
                                             comparison = .x,
                                             subset.factor = "SUBSET_COL",
                                             subset.levels = subset_level,
                                             methods = gsea_methods,
                                             assay = "counts",
                                             output.dir = tempfile(),
                                             save.results = FALSE),
                  .progress = TRUE) %>%
      purrr::set_names(glue::glue("{subset_level}:{names(.)}"))
  }) %>%
  purrr::compact() %>%
  purrr::list_c() %>%
  basicBulk::tidyGSEAlist(GSEAmethod = gsea_methods)
```

Then create the DGE data and significance tibble:

```r

  basicBulk::makeDGEdata(voomList)

sigTibble <- DGEdata %>%
  basicBulk::makeSigTibble()
```

### Pattern 3 Downstream Visualization

Pattern 3's prefixed DGEdata names (e.g., `Neuron:DrugA vs PBS`) need the subset dimension and treatment extracted for faceting. After `stringr::str_remove(" vs .*")`, names become `Neuron:DrugA`. Define a `tidyContrasts()` helper that parses both. Replace `SUBSET_COL` with the subset column (e.g., `CellType`, `Tissue`) and `CONTRAST_VAR` with the treatment variable (e.g., `Drug`, `Molecule`, `Dose`):

```r
tidyContrasts <- function(.x, .y) {
  .y <- stringr::str_remove(.y, " vs .*")
  .x %>%
    dplyr::mutate(
      SUBSET_COL = stringr::str_extract(.y, "^[^:]+") %>%
        factor(levels = unique(se$SUBSET_COL)),
      CONTRAST_VAR = stringr::str_extract(.y, "(?<=:).+") %>%
        factor(levels = levels(se$Group))
    )
}
```

Replace `SUBSET_COL` with the actual column name. The facet formula uses both dimensions so each contrast gets its own panel:

```r
sigCountTibble %>%
  tidyContrasts(., .$contrast) %>%
  basicBulk::DEGbar() +
  ggplot2::aes(x = CONTRAST_VAR) +
  ggplot2::facet_wrap(~ SUBSET_COL, scales = "free")
```

`basicVolcano()`'s per-panel DEG counts are a separate label layer keyed only by `contrast`, so before re-faceting, add the `tidyContrasts()` columns to that layer too. Otherwise `ggh4x::facet_nested()` repeats every contrast's counts in every panel. List every column your `tidyContrasts()` adds in `c(...)`.

```r
volc <- DGEdata %>%
  purrr::set_names(names(.) %>% stringr::str_remove(" vs .*")) %>%
  purrr::imap(tidyContrasts) %>%
  basicBulk::basicVolcano(style = "enhanced")

volc$layers <- purrr::map(volc$layers, function(ly) {
  d <- ly$data
  if (is.data.frame(d) && "contrast" %in% names(d) && !all(c("SUBSET_COL", "CONTRAST_VAR") %in% names(d)))
    ly$data <- tidyContrasts(d, d$contrast)
  ly
})

volc +
  ggh4x::facet_nested(SUBSET_COL ~ CONTRAST_VAR,
                      scales = "free", space = "free")
```

## Pattern 4: Crossed Multi-Factor Split

When: contrasts are crossed across two variables. For example, Drug vs Vehicle compared within each combination of brain Region and animal Cohort. Uses `tidyr::crossing()` to iterate over all combinations. User must confirm both split variables. Often combined with `dc.block`.

```r
control <- levels(se$Group)[1]

comparisonList <- levels(se$Group)[c(2:nlevels(se$Group))] %>%
  purrr::map(~ list(.x, control) %>%
               purrr::list_c())

splitVoom <- function(SPLIT_VAR_1, SPLIT_VAR_2) {
  splitSe <- se %>%
    dplyr::filter(SPLIT_COL_1 == !!SPLIT_VAR_1 & SPLIT_COL_2 == !!SPLIT_VAR_2) %>%
    dplyr::mutate(Group = forcats::fct_drop(Group))

  split_groups <- levels(splitSe$Group)

  if (!control %in% split_groups || length(split_groups) < 2) {
    message(glue::glue("Skipping {SPLIT_VAR_1}:{SPLIT_VAR_2} — control missing or fewer than 2 groups"))
    return(NULL)
  }

  valid_comparisons <- comparisonList %>%
    purrr::keep(~ all(.x %in% split_groups))

  if (length(valid_comparisons) == 0) {
    message(glue::glue("Skipping {SPLIT_VAR_1}:{SPLIT_VAR_2} — no valid comparisons"))
    return(NULL)
  }

  voomList <- splitSe %>%
    augere.de::runVoom(groups = "Group",
                       dc.block = DC_BLOCK,
                       comparisons = valid_comparisons,
                       assay = "counts",
                       output.dir = tempfile(),
                       save.results = FALSE) %>%
    magrittr::extract2("results")

  splitSe %>%
    basicBulk::makeDGEdata(voomList = voomList) %>%
    purrr::set_names(glue::glue("{SPLIT_VAR_1}:{SPLIT_VAR_2}:{names(.)}"))
}

# compute chunk (build + save; no printing)
DGEdata <- tidyr::crossing(
  SPLIT_VAR_1 = unique(se$SPLIT_COL_1) %>% forcats::as_factor(),
  SPLIT_VAR_2 = unique(se$SPLIT_COL_2) %>% forcats::as_factor()
) %>%
  purrr::pmap(~ with(list(...),
                     splitVoom(SPLIT_VAR_1 = SPLIT_VAR_1, SPLIT_VAR_2 = SPLIT_VAR_2)),
              .progress = TRUE) %>%
  purrr::compact() %>%
  purrr::list_c()

sigTibble <- DGEdata %>%
  basicBulk::makeSigTibble()

# display chunk, under the `## Significant Genes` header (SKILL.md Section 4)
sigTibble %>%
  basicBulk::printSigTibble()
```

Replace `SPLIT_COL_1`/`SPLIT_COL_2` with the actual splitting columns such as `Region`, `Study`, or `Timepoint`. Replace `DC_BLOCK` with the repeated-measures column such as `"Animal"`, or omit `dc.block` if not needed.

GSEA follows the same split pattern with a `splitGSEA()` helper function:

```r

  }

                                           groups = "Group",
                                           dc.block = DC_BLOCK,
                                           comparison = .x,
                                           methods = gsea_methods,
                                           assay = "counts",
                                           output.dir = tempfile(),
                                           save.results = FALSE),
                .progress = TRUE) %>%
    purrr::set_names(glue::glue("{SPLIT_VAR_1}:{SPLIT_VAR_2}:{names(.)}"))
}

set.seed(100)
GSEAlist <- tidyr::crossing(
  SPLIT_VAR_1 = unique(se$SPLIT_COL_1) %>% forcats::as_factor(),
  SPLIT_VAR_2 = unique(se$SPLIT_COL_2) %>% forcats::as_factor()
) %>%
  purrr::pmap(~ with(list(...),
                     splitGSEA(SPLIT_VAR_1 = SPLIT_VAR_1, SPLIT_VAR_2 = SPLIT_VAR_2)),
```

## Pattern 4 Downstream Visualization

Pattern 4's prefixed DGEdata names (e.g., `SPLIT_VAR_1:SPLIT_VAR_2:CONTRAST_VAR vs Control`) break functions that parse contrast strings, particularly `basicHeatmap()`. Pattern 4 requires a different visualization approach from Pattern 1/2: use `tidyContrasts()` + `ggh4x::facet_nested()` for plots, and pre-filtered SE + sigTibble for heatmaps.

### `tidyContrasts()` Helper

Generate this per-study based on the split columns. It extracts split dimension values and the treatment from the colon-prefixed contrast names into columns for `ggh4x::facet_nested()`. Names after `str_remove(" vs .*")` are `SPLIT_VAR_1:SPLIT_VAR_2:CONTRAST_VAR`. Replace `SPLIT_COL_1`/`SPLIT_COL_2` with the split columns (e.g., `Region`, `Cohort`) and `CONTRAST_VAR` with the treatment variable (e.g., `Drug`, `Molecule`, `Dose`):

```r
tidyContrasts <- function(.x, .y) {
  .y <- stringr::str_remove(.y, " vs .*")
  .x %>%
    dplyr::mutate(
      SPLIT_COL_1 = stringr::str_extract(.y, "^[^:]+") %>%
        factor(levels = unique(se$SPLIT_COL_1)),
      SPLIT_COL_2 = stringr::str_extract(.y, "(?<=:)[^:]+(?=:)") %>%
        factor(levels = unique(se$SPLIT_COL_2)),
      CONTRAST_VAR = stringr::str_extract(.y, "[^:]+$") %>%
        factor(levels = levels(se$Group))
    )
}
```

Replace `SPLIT_COL_1`/`SPLIT_COL_2` with the actual split columns. The facet formula must include `CONTRAST_VAR` so each contrast gets its own panel:

## Custom Design Matrix

Use a custom design matrix when you must **average two or more controls** into one baseline
(several non-targeting / scramble / NTC controls), or for interaction terms / other contrasts the
`comparisons =` interface can't express. The **same `design` + `contrastList` drive both
`augere.de::runVoom(design =, contrasts =)` and `augere.gsea::runContrast(design =, contrast =)`** — the
key difference from Patterns 1–4, which pass `groups`/`comparisons`. User must confirm the custom design.

**Which recipe?** The discriminator is whether you must *average* multiple controls. A single
control needs no custom design — use the subset patterns instead:

| Controls to average | Second factor (e.g. dose) | Use |
|---|---|---|
| One | One — same comparison per level | **Pattern 3** (`subset.factor`), not a custom design |
| One | Two — crossed | **Pattern 4** |
| Two or more (average) | None | Custom design — **single-factor block** below |
| Two or more (average) | One | Custom design — **crossed block** below |

Placeholders. **Single-factor block:** `TREATMENT_LEVELS` / `CONTROL_LEVELS` are the tested and
to-be-averaged **group levels** (here a group level is just the molecule, no second factor).
**Crossed block:** group levels are `{molecule}_{secondaryLevel}`, so `TREATMENT_MOLECULE` /
`CONTROL_MOLECULES` are the molecule-part labels and `SECONDARY_FACTOR` is the second-factor
column (e.g. a dose or timepoint column) whose levels each get their own averaged contrast — the
same `SECONDARY_FACTOR` used for plot shape in `references/optional-sections.md` (Secondary-Factor Aesthetics).

Build the design from `se` and strip the `Group` prefix so contrast strings read as the
group levels themselves:

```r
design <- se %>%
  SummarizedExperiment::colData() %>%
  tibble::as_tibble() %>%
  stats::model.matrix(object = ~ 0 + Group, data = .)   # fixed-effect blocks (incl. Batch Option B) go in the FORMULA here: ~ 0 + Group + BLOCK

colnames(design) <- stringr::str_remove(colnames(design), "Group")
```

**Single-factor block** — average the controls into one baseline. `glue::glue_collapse()` builds
the `(ctrlA + ctrlB + ...)/N` mean; `glue` vectorizes over `TREATMENT_LEVELS` to give one contrast
per tested group, each vs the same averaged baseline. **Name each contrast with the distinguishing
token *before* `" vs "`** so the default `stringr::str_remove(" vs .*")` label-stripping yields
distinct labels:

```r
contrastVector <- glue::glue("{TREATMENT_LEVELS} - {control}",
                             control = CONTROL_LEVELS %>%
                               glue::glue_collapse(sep = " + ") %>%
                               paste0("(", ., ")/", length(CONTROL_LEVELS))) %>%
  as.character() %>%
  purrr::set_names(glue::glue("{TREATMENT_LEVELS} vs Control"))

contrastList <- contrastVector %>%
  purrr::map(~ limma::makeContrasts(contrasts = ., levels = design))
```

**Crossed block** — average the controls *within* each level of `SECONDARY_FACTOR` (e.g. treatment
vs the mean control at each dose/timepoint). Group levels are named `{molecule}_{secondaryLevel}`;
build one averaged contrast per second-factor level. The inner `glue_collapse` keeps the baseline
N-control-general (not limited to two controls), and the second-factor token stays before `" vs "`
so it survives label-stripping:

```r
contrastVector <- levels(se$SECONDARY_FACTOR) %>%
  purrr::map_chr(~ glue::glue("{TREATMENT_MOLECULE}_{.x} - {control}",
                              control = glue::glue("{CONTROL_MOLECULES}_{.x}") %>%
                                glue::glue_collapse(sep = " + ") %>%
                                paste0("(", ., ")/", length(CONTROL_MOLECULES)))) %>%
  purrr::set_names(glue::glue("{TREATMENT_MOLECULE} {levels(se$SECONDARY_FACTOR)} vs Control"))

contrastList <- contrastVector %>%
  purrr::map(~ limma::makeContrasts(contrasts = ., levels = design))
```

For crossed volcano grids, use Pattern 4's count-layer step, adapting `tidyContrasts()`, the column list, and the facet formula to the custom contrast names (e.g. `molecule ~ dose`).

Run voom with the custom design + contrast list, then build the DGE data and significance tibble
exactly as the other patterns. **A custom `design =` bypasses `block =`/`covariates =`** (`runVoom`
builds the model from your matrix, not from those arguments — verified: only the non-custom path
consumes them), so a `block = "BLOCK"` passed alongside a custom design is **silently ignored**. A
fixed-effect blocking variable — including **Batch under Option B** — must therefore be a term in
the design formula (`~ 0 + Group + BLOCK`), not a `block =` argument. `dc.block` is the exception:
it is **not** bypassed by a custom design (it is applied at the `lmFit`/`duplicateCorrelation`
step regardless), so `dc.block = "BLOCK"` works with a custom design and `dc.block = "Batch"`
(Batch Option A) needs no change to the matrix. Use *either* a design-matrix `+ BLOCK` term *or*
`dc.block = "BLOCK"`, never both:

```r
# compute chunk (build + save; no printing)
voomList <- se %>%
  augere.de::runVoom(design = design,
                     contrasts = contrastList,
                     assay = "counts",
                     output.dir = tempfile(),
                     save.results = FALSE) %>%
  magrittr::extract2("results")

DGEdata <- se %>%
  basicBulk::makeDGEdata(voomList)

sigTibble <- DGEdata %>%
  basicBulk::makeSigTibble()

# display chunk, under the `## Significant Genes` header (SKILL.md Section 4)
sigTibble %>%
  basicBulk::printSigTibble()
```

GSEA loops `augere.gsea::runContrast()` over the **same `contrastList`**, passing the full `design` and the
**single `contrast = .x`** (the GSEA analogue of the `runVoom` call above — `runContrast` takes
one contrast at a time, so loop with `imap`). Coefficients for groups a contrast doesn't reference
are zero, so camera/fry test only the intended comparison. The `contrastList` names carry through
`imap` into `GSEAlist`, so no separate `set_names` is needed:

```r
set.seed(100)
GSEAlist <- contrastList %>%
  purrr::imap(~ augere.gsea::runContrast(se,
                                         sets = gene.sets,
                                         design = design,
                                         contrast = .x,
                                         methods = gsea_methods,
                                         assay = "counts",
                                         output.dir = tempfile(),
                                         save.results = FALSE),
              .progress = TRUE) %>%
  basicBulk::tidyGSEAlist(GSEAmethod = gsea_methods)
```

To restrict each GSEA fit to *only* the groups its contrast references (instead of the full
design — e.g. to estimate variance within just the compared groups), identify those groups from
the contrast's non-zero coefficients and subset the samples, design columns, and contrast rows
together. `design`'s rows are in `se`'s column (sample) order — it was built from
`colData(se)` without reordering — so the same logical `keep` indexes both safely:

```r
set.seed(100)
GSEAlist <- contrastList %>%
  purrr::imap(~ {
    used <- rownames(.x)[.x[, 1] != 0]          # group levels this contrast references
    keep <- se$Group %in% used                  # samples in those groups

    augere.gsea::runContrast(se[, keep],
                             sets = gene.sets,
                             design = design[keep, used],
                             contrast = .x[used, , drop = FALSE],
                             methods = gsea_methods,
                             assay = "counts",
                             output.dir = tempfile(),
                             save.results = FALSE)
  }, .progress = TRUE) %>%
  basicBulk::tidyGSEAlist(GSEAmethod = gsea_methods)
```

The full-design form above is simpler and sufficient in most cases.
